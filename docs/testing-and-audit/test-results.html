Findings & Issues Filed

⚠️
No test failures. Writing the integration tests surfaced one real product gap in AuthController, tracked as a GitHub issue rather than a test failure (the test asserts the current stub behavior so it stays green until fixed).

Auth refresh & logout are unimplemented stubs

AuthController.Refresh always returns 401 Unauthorized and AuthController.Logout is a no-op — both are marked // TODO in source and never call into a data handler. The Phase 8 integration test plan (integrationtesting.md) assumed a full login → refresh → logout round trip; that flow cannot be completed end-to-end today.

Filed as GitHub issue #5.

▶️

How to Reproduce

cd src
dotnet test HCM.Application.Tests\HCM.Application.Tests.csproj --logger "trx;LogFileName=unit-results.trx"
dotnet test HCM.API.Tests\HCM.API.Tests.csproj --logger "trx;LogFileName=integration-results.trx"

Docker Desktop's engine wasn't running in this environment, so the integration suite substitutes EF Core's InMemory provider for the Testcontainers-backed SQL Server described in the original plan, and a fake IBlobStorageService for Azurite/Azure Blob. Both are swapped in purely via DI overrides in ApiFactory — the controllers, middleware, JWT auth, and RBAC policies under test are the real production code. DataSeeder now branches on Database.IsInMemory() (EnsureCreated vs. Migrate) to support this.
